# 53230A 实时频率稳定度分析器（Python）

这是原 MATLAB 项目的独立 Python 实现。它不会修改或调用原项目中的任何文件，也不需要 MATLAB、MATLAB Runtime 或 Instrument Control Toolbox。

## 已实现

- 点击“开始采集”后持续运行，直到人工点击“停止”，无需输入测量时长或总点数。
- 53230A 使用 `FREQ:MODE CONT` 和指定的 Gate time，在同一连续测量序列中采集无死时间频率读数。
- 采集期间不断用 `DATA:REM?` 排空仪器读数内存，并追加到本地 `measurements.csv`。
- 独立分析线程持续计算重叠 Allan 偏差和重叠 Hadamard 偏差，GUI 实时刷新频率曲线和稳定度曲线。
- 完整原始数据始终写盘；内存只保留设定的最近分析窗口，支持长时间运行而不无限占用内存。
- 内置模拟数据模式，可在没有仪器时检查 GUI、保存和实时分析流程。
- 硬件模式支持独立“测试连接”：严格解析 `*IDN?` 的厂商、型号、序列号和固件，并在采集元数据中保存连接验证时间。
- 硬件模式必须依次通过“测试连接”和“写入并检查参数”才能开始采集；修改 IP/端口/模式会清空两级验证，修改通道、Gate time 或输入阻抗只清空参数验证。模拟模式也遵守相同的两阶段流程。
- “写入并检查参数”会执行完整 SCPI 配置、严格判定 `*OPC? == 1`、排空错误队列，并读回测量通道、连续模式、Gate、输入、触发、采样、数据格式、字节序和仪器超时等关键参数；逐项结果写入 `metadata.json`。
- `INIT` 后会验证错误队列和操作状态，首个有效读数必须在限时内到达；运行中无数据超时、通信取消和 Reading Memory Overflow 都会明确结束会话并写入原因。

## 启动

双击 `启动程序.bat`。当前电脑的 `py311` 环境已包含 NumPy、Matplotlib 和 Tkinter。

也可以在本目录执行：

```powershell
python -m pip install -r requirements.txt
python main.py
```

## 使用

1. 硬件模式输入 53230A 的 LAN IP，确认电脑可以访问仪器的 TCP 5025 端口；模拟模式使用独立的模拟数据开关。
2. 点击“测试连接”，确认返回的厂商和 53230A 型号。
3. 选择通道、Gate time 和输入阻抗，然后点击“写入并检查参数”，确认每项读回检查通过。
4. 参考频率填实际标称频率；填 `0` 时，每次分析使用当前分析窗口的平均频率。
5. 两阶段检查均通过后点击“开始采集”。点击“停止”后，程序会取消阻塞读操作、停止仪器并保存缓冲区中的剩余读数。

每次运行创建一个时间命名的目录：

- `measurements.csv`：所有频率读数和时间字段，持续追加写入。
- `deviations_latest.csv`：最近一次实时 Allan/Hadamard 结果。
- `metadata.json`：仪器身份、连接和首读数时间、参数逐项读回结果、实际 Gate time、输入诊断、运行状态、停止原因、错误和点数等信息。

`segment_elapsed_s` 是当前连续段内的样本序号乘仪器返回的实际 Gate time；`estimated_unix_s` 以电脑发出本段 `INIT` 后的时间为起点估算；`received_unix_s` 是电脑收到该批数据的时间。这些均不是仪器硬件时间戳。`continuous_sample_elapsed_s` 不包含段间重启时间，不能用来证明跨段连续性。

## 无死时间和长期运行边界

53230A 的连续频率模式会让相邻读数共用结束/开始边沿，因此在一个采样序列内无死时间。但是官方手册明确规定：该模式只接受一个触发，而且每个采样序列最多 100 万点。因此“无限时长”和“全程严格无死时间”不能同时由这台仪器实现。

程序采用可审计的折中：每满 100 万点自动重新启动下一段，持续运行和记录，但 CSV 用 `continuity_segment` 明确标出边界，实时 Allan/Hadamard 计算会在新段开始时清空分析窗口，绝不跨越可能有死时间的段边界。单段持续时间约等于 `1,000,000 × Gate time`，例如 Gate time 为 0.1 秒时约 27.8 小时。网络、电脑磁盘或进程异常也可能造成数据缺口。程序每 2 秒检查 Reading Memory Overflow 状态，一旦发现溢出会停止并明确报错，不会把缺失数据静默当作连续数据。

首个有效读数的默认等待上限为 `max(5 秒, 3 × Gate time + 2 秒)`；开始产生数据后，连续超过同一上限没有新读数也会触发 no-data watchdog。底层 API 可通过 `SessionSettings(first_read_timeout_s=..., no_data_timeout_s=...)` 调整这两个边界。
